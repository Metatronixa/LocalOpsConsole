Updates

By default the app checks https://www.opsconsole.co.za/uploads/update.json and downloads the ZIP named in that manifest (GitHub Release or a mirrored build under uploads/builds/).

Production feed

Host / deploy update.json at:

https://www.opsconsole.co.za/uploads/update.json

Default settings.json:

"updateUrl": "https://www.opsconsole.co.za/uploads/update.json"

Manifest shape

{
  "name": "LocalOpsConsole",
  "latest": "2.1.2",
  "releasedAt": "2026-08-05T00:00:00Z",
  "notes": "Release notes",
  "minVersion": "1.0.0",
  "builds": [
    {
      "version": "2.1.2",
      "channel": "stable",
      "url": "https://github.com/Metatronixa/LocalOpsConsole/releases/download/v2.1.2/LocalOpsConsole-2.1.2.zip",
      "sha256": "REPLACE_WITH_SHA256",
      "size": 0
    }
  ]
}

Relative URLs (e.g. builds/LocalOpsConsole-x.y.z.zip) resolve against the directory that contains update.json — useful if you also mirror ZIPs under https://www.opsconsole.co.za/uploads/builds/.

In the dashboard

  1. On load, the UI calls GET /api/v1/updates/check.
  2. If latest is newer than local VERSION, an update banner appears.
  3. Confirm to run POST /api/v1/updates/apply — download, SHA-256 verify, extract (preserving logs/ and local settings.json), then restart.

Publishing a release

  1. Bump VERSION and run .\build.ps1 -PublishWebsite.
  2. Attach ZIPs to the GitHub Release; refresh website/uploads/update.json with SHA-256.
  3. Deploy website/uploads/update.json (and optional builds/) to www.opsconsole.co.za/uploads/.
Note: Updates are never silent. The operator must confirm apply. Rely on HTTPS + SHA-256.
