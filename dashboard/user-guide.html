User Guide

Complete operator manual for LocalOpsConsole v2.2.0 — how every major surface works, and exactly what you must do to install, run, and manage Windows endpoints safely.

Local-first. The console runs on your Windows PC. The dashboard is an offline SPA; the API is PowerShell HttpListener (default http://localhost:8787/). Nothing requires a cloud account. Optional fleet agents phone home outbound to this console.

1. What LocalOpsConsole is

LocalOpsConsole is a Windows Operations Platform for IT pros, MSPs, system admins, and power users. It combines:

  • Plugin diagnostics & remediations — modules for services, storage, printers, updates, network, security, and more
  • Event Intelligence — watchers + JSON rules that open incidents instead of dumping raw Event Viewer noise
  • Security Baseline — read-only posture audit (Defender, Firewall, BitLocker, TPM, …)
  • Optional fleet — LocalOps Agent on other PCs for heartbeat, remote commands, and repair actions

The Overview page answers one question first: Is this computer healthy? (health score + security score + active incidents).

2. What you must do (checklist)

  1. Obtain a licensed build via Get Access (official packages are not free public downloads).
  2. Extract to a writable folder and run start.bat (accept UAC once for remediations).
  3. The browser opens automatically at http://localhost:8787/ — there is no leftover console window on success.
  4. Confirm the elevation badge in the header — STANDARD USER vs elevated admin.
  5. Use header Restart / Shutdown to control the server (not a console Ctrl+C).
  6. For other PCs: set bindHost to 0.0.0.0, set fleetPublicUrl to your LAN/Tailscale URL, restart, then install the agent with that URL (never localhost on the remote PC).
  7. When an update banner appears, review notes and confirm — updates are never silent.
  8. Do not expose the API to the public internet.

3. Install & launch

3.1 Licensed package

  1. Request access at opsconsole.co.za/get-access (email bradford.lotriet@gmail.com).
  2. Extract the delivered LocalOpsConsole-x.y.z.zip to e.g. C:\Tools\LocalOpsConsole.
  3. Double-click start.bat (or start-silent.vbs for zero console flash — shortcuts / Startup folder).
  4. Accept UAC. The browser opens Overview when the API is healthy.

3.2 Developers (source)

git clone https://github.com/Metatronixa/LocalOpsConsole.git
cd LocalOpsConsole
.\start.bat

Source is for development and review. Production operators should use licensed builds.

3.3 What start.bat does (headless)

  • Starts PowerShell hidden, elevates once if needed (also hidden), then starts api\server.ps1 hidden
  • Waits for /api/v1/health, writes data/runtime/server.pid, opens the browser, and exits — no Wait-Process console stays open
  • On failure, opens a short visible PowerShell window with the error and “Press Enter”
  • For verbose progress: powershell -File start.ps1 -ShowConsole
Failed to fetch on every tile means the server process is not running. Use start.bat again (or UI Restart if the tab is still up). Check logs\YYYY-MM-DD.log.

4. UI tour

After splash, the shell has four zones:

  1. Header — brand + version (left), live telemetry chips (center), elevation badge + engine status + Help + Restart + Shutdown (right)
  2. Sidebar — platform sections and modules (filtered by profile)
  3. Main pane — the active module view
  4. Live console — streaming output from diagnostics/actions as they run

Optional chrome:

  • Update banner — when a newer licensed build is available via updateUrl
  • Alerts — notification center access from monitoring surfaces
  • Help — opens this User Guide inside the app (/user-guide.html)

Restart & Shutdown

  • Restart — schedules a headless relaunch of the API (inherits elevation; no second UAC), stops the listener, then the UI polls /health and reloads when the server is back.
  • Shutdown — stops the server cleanly. Use start.bat to bring it back.

There is no launcher console to Ctrl+C after a successful start — the UI is the control surface.

7. Overview, Health Center, Security Center

Overview

Landing page after launch. Shows health score, security score, and active incidents. Use it as your triage start — then open the related module.

Health Center

Deeper health checks for the local machine. Run diagnostics from the module actions; watch the live console for script output.

Security Center

Aggregated security posture. Prefer this and Security Baseline for “are we compliant?” questions rather than raw Event Log scrolling.

8. Event Intelligence, Incidents, Monitoring

When eventIntelEnabled is true in settings.json (default on):

  1. Watchers observe Windows Event Logs and related signals
  2. Rules under rules/ evaluate normalized events
  3. Correlation opens or updates an incident
  4. Notifications respect severity, selected channels, quiet hours, and maintenance windows
  5. Automation runs only when you enable the playbook on the Automation page (toggles apply immediately)
Event ID 4104 (PowerShell Script Block Logging) may appear when the console starts api\server.ps1. That is Windows logging the host process — not automatically an attack.

Incident Center

List and open correlated incidents. Resolve when the underlying condition is cleared. Archives follow retention in Event Intel settings.

Notification Center & Event Timeline

Alerts and a timeline of observed events. Use Timeline for forensics; Incidents for “what should I act on?”

9. Security Baseline, Threat Operations, Event Log

Security Baseline

  1. Open Security → Security Baseline
  2. Choose This PC or an enrolled fleet agent
  3. Click Run Audit (read-only — does not change the system)
  4. Review score, risk rating, per-control results, and recommendations

This PC uses the full module audit. Fleet queues AuditSecurityBaseline (agent 2.2.0+). Apply hardening-basic stays on Computers → Policy. You can open this page with an agent preselected from the drawer.

Controls typically cover Defender, Firewall, BitLocker, TPM, Secure Boot, and related posture checks (fleet audit is a compact set of those controls).

Threat Operations

Open Security → Threat Operations for a live security event stream:

  • Filter by severity, host, and keyword
  • Inspect ScriptBlock / encoded command payloads (decoded when possible)
  • Fleet agents can forward security telemetry via HMAC to POST /api/v1/fleet/threat-telemetry
  • Events are stored under data/threat/ (JSONL + retention), not a cloud SIEM

See also docs/modules/ThreatOperations.md.

Security module & Event Log

Dedicated views paint the UI first, then load data asynchronously with bounded WinEvent queries. “Access denied” on the Security channel without elevation is normal.

Integrity gate

Before a module diagnostic/action runs, the engine checks:

  1. Manifest validation
  2. SHA-256 integrity (warn in source; enforce in packaged builds)
  3. Elevation / permissions
  4. Dependencies
  5. Parameter allow-list
  6. Path jail

Set integrityMode to warn only while developing local modules. Releases ship as enforce.

10. Operations modules

Each module follows the same pattern: open the sidebar entry → run a diagnostic (inspect) or action (change) → watch the live console. Admin-required actions stay locked until elevated.

Active Directory, DNS, DHCP, Group Policy, Hyper-V, Certificates, Server Operations

Infrastructure modules for domain health, name resolution, scopes, GPO refresh/health, Hyper-V hosts/VMs, certificate stores, and local server service/disk/share checks. Availability depends on Windows roles/features and elevation.

System (Performance)

Live telemetry for CPU, memory, disk, network, GPU. Use when investigating spikes on the console PC itself.

Services

List and manage Windows services — inventory, status, restart where permitted.

Storage

Disk inventory, capacity, and storage-related diagnostics/remediations.

Printers

Printer inventory and common print-path repairs (including spooler-related workflows).

Updates

Windows Update status and install flows for the local machine. For remote PCs, use the Computers drawer Windows Update actions.

Tools & Configuration

Utility diagnostics and configuration catalog helpers used by support workflows.

Network, VPN, Internet Health

  • Network — adapter and connectivity focused checks
  • VPN — VPN presence/status when configured
  • Internet Health — DNS, latency, connectivity tests and repairs (includes speed-test related diagnostics)

Remote

Discover hosts, shares, open files/sessions, and remote registry style inspections on the LAN (subject to Windows permissions).

Remote Support (RustDesk)

RustDesk status and optional silent install. Configure rustDeskInstallerUrl (HTTPS) and optional SHA-256 in settings.json before remote install from the fleet drawer.

Audio

Audio device diagnostics for workstation support.

Automation

Central hub: opt-in playbooks with scope This PC / Fleet / Both, optional agent multi-select, and Run now (sticky status). Event Intel auto still remediates This PC when scope includes local. High-CPU fleet spikes can auto-run the high-CPU snapshot playbook when enabled for fleet. Full agent Event Log auto-remediation is Hub v2.

Risk badges: Safe (observe/cleanup) · Careful (may restart services, clear jobs, or briefly disrupt network) · Notify (timeline only).

Built-in pack includes Spooler recovery, low-disk cleanup, monitored service restart, clear print queue, network soft repair (DNS/DHCP), update stack restart, high-CPU process snapshot, and notify-only playbooks for Event Log / Defender / firewall / unexpected reboot. Authors can still add definitions under rules/custom/.

11. Computers (fleet) — deep guide

Fleet is optional. The console is fully useful offline on one PC. Agents are outbound-only — no inbound listener on managed desktops.

11.1 Concepts

  • Shared enroll token — used only for first join; rotate in Computers → Enrollment if leaked
  • Per-agent secret — after enroll, each PC gets AgentId + AgentSecret; API calls are HMAC-signed
  • Heartbeat — roughly every 30s (CPU, RAM, disk, network, uptime, disk IO, …)
  • Command poll — roughly every 3s; agent claims one command at a time and will not claim while another is Running

11.2 Prepare the console for remote agents

  1. Edit settings.json:
{
  "bindHost": "0.0.0.0",
  "port": 8787,
  "fleetPublicUrl": "http://192.168.1.10:8787",
  "fleetEnabled": true
}
  1. Replace the IP with this PC’s LAN IPv4 or Tailscale IP.
  2. Restart via start.bat (accept UAC). Allow inbound TCP 8787 in Windows Firewall if prompted.
  3. Open Operations → Computers. Copy the enrollment token and install one-liner.
Prefer bindHost: 0.0.0.0 over binding HttpListener to a single LAN IP (HTTP.sys URL ACL conflicts are common). The server maps 0.0.0.0 to all interfaces and still listens on localhost for the local UI.

11.3 Install the agent on another PC

  1. Copy LocalOpsAgent-x.y.z.zip (or the agent folder) to the target PC.
  2. Extract and run as Administrator:
.\Install-LocalOpsAgent.ps1 -ServerUrl "http://192.168.1.10:8787" -EnrollToken "YOUR_TOKEN"
  1. Confirm the PC appears Online under Computers.

The installer copies the agent to C:\Program Files\LocalOpsAgent\, writes C:\ProgramData\LocalOpsAgent\config.json, registers scheduled task LocalOpsAgent (SYSTEM at startup), and starts it.

11.5 Command queue behavior

  • Click a Command history row to open its result in the result panel.
  • If one command stays Running, newer work stays Pending until it finishes, times out (~45 minutes), or you click Clear stuck.
  • Failed: Unknown command type means the agent is too old — reinstall/update the agent for newer command types.

11.6 Publish agent package & self-update

  1. Computers → Enrollment → Publish agent package (copies agent script + SHA-256 into data/fleet/agent-package/)
  2. On a PC drawer → Update agent
  3. Agent downloads over HMAC, verifies hash, replaces Program Files script, restarts the task

11.6b Software catalog (local packages)

  1. Copy installer to data/fleet/software/{Id}/ on the console (e.g. wintax/WintaxSetup.exe)
  2. Computers → Manage software catalog → Add local → Register (computes SHA-256)
  3. PC drawer → Software → Install. Agent GETs /api/v1/fleet/packages/{id}/content with HMAC, verifies hash, runs SilentArgs

Seed catalog includes Chrome, Edge, Firefox, Reader, 7-Zip, VC++ redist, WinRAR, and WinDirStat (winget). Multipart browser upload of huge ISOs is out of scope — drop files on disk.

11.7 Uninstall agent

.\Uninstall-LocalOpsAgent.ps1

Or use Remove agent from the drawer (deletes the fleet record on the console).

12. Network Map

Under Operations, Network Map shows enrolled agents and discovered LAN neighbors grouped by gateway cluster (agents on an inner ring, LAN on outer rings that grow with node count). This is not a fixed star topology — crowded maps get more space, and you can switch to List for a sortable table. Use the Agents / LAN / Offline filters on either view, then open Computers for actions.

13. SyncMe

SyncMe integration expects a local SyncMe install path.

  1. Set syncMePath in settings.json (or register via the SyncMe module / register API).
  2. Open Operations → SyncMe.
  3. Use diagnostics for status; actions to open console, open download page, or start backup as exposed by the module.

Registration state is stored under data/syncme/ (runtime JSON is gitignored).

16. In-app updates

  1. On launch (and periodically), the app fetches updateUrl (default opsconsole.co.za feed for licensed operators).
  2. If latest is newer than the running version, the banner appears.
  3. You choose Update now or Later — never silent.
  4. The feed includes SHA-256 for the ZIP; verify downloads.

Maintainers: bump VERSION, run .\build.ps1 -PublishWebsite, publish the licensed package to the private/customer channel, deploy website/uploads/update.json with the matching SHA. Do not advertise public free downloads.

17. Access model & elevation

ModeWhat works
STANDARD USERMost diagnostics and read-only views

The header badge shows current elevation. If an action is locked, restart via start.bat and accept UAC.

19. Safety policy

  • Default bind is localhost only
  • Privileged actions are declared per module
  • Automation is off unless enabled on the Automation page
  • Packaged builds enforce module integrity
  • Do not expose the API to the public internet
  • See SECURITY.md in the repository
